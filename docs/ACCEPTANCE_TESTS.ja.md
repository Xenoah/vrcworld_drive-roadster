# 公開前の実機受入テスト

2026-10-17: Unity C# / UdonSharp コンパイルと ClientSim の限定区間スモーク試験は実施済み。結果と条件は [Unity 検証記録](validation/UNITY_VALIDATION.ja.md) を参照。以下の実クライアント・VR・複数人受入試験は未実施。Python 検査や ClientSim はこれらを代替しない。

## コンパイル/シーン
- VCC WorldsプロジェクトでC#とUdonSharpの両コンパイルが成功する。
- BuilderのコースJSON、FBX、Material参照、COL_形状、座席、移動先が正しい。
- SDK Validationが成功し、Build & Testがロードする。
- 車両原点・FBX軸・車輪回転軸・座席の高さを目視確認する。

## 2クライアント以上
1. Aが運転し、Bから位置・姿勢と占有状態を確認。
2. A/Bがほぼ同時に乗車。最終ownerだけ運転し、敗者が退出する。
3. 運転中にCが途中参加。車両状態と記録が復元される。
4. Aが通常退出、切断、インスタンス移動をそれぞれ実施。車両が一度だけ復帰する。
5. 権限移譲後に旧driverが操作しても新driverの車が動かない。
6. メニュー開閉、低FPS、遅延時に入力が張り付かず、補間が暴走しない。
7. 所有権変更時に記録配列が消えない。旧runが完走扱いにならない。

## 周回/安全
- 正規コースを通って1回だけ完走する。
- START逆走、WALL_APEXを地上ショートカット、空中ゲート飛ばし、横抜け、二重接触は記録されない。
- 高速でもゲート面の交差を検出し、リセットのワープでゲートが進まない。
- 地上→壁→飛行→着地の状態遷移が振動しない。
- 車両復帰中、切断後、再走行開始時に以前のタイマーが残らない。
- 車内ボタンと通常退出がPC/VR両方で使え、退避先が路面内にない。
- 1台でフレーム時間と送信量を記録。4台への拡張はこの試験後。

## 記録するもの
Unity/SDKバージョン、テスト端末、人数、HMD/Hz、CPU/GPUフレーム時間、ログ、結果、再現手順、修正後再試験。性能値とVR快適性を推測で合格にしない。

## クラウドで実行できる限定検査

- `python -m unittest discover -s tests -v`: ソース契約とゲート数理例
- `python -m unittest discover -s Tests/Review -v`: 独立ゲート数理・manifest検査
- `python -m pip install -r tools/requirements-validation.txt` 後 `python tools/check_csharp_syntax.py`: C#の構文解析
- Blender原本/FBXの幾何検査とレンダーは各SourceAssets配下の手順を使用

これらが成功してもUnity/Udonコンパイルや実マルチプレイの成功とはしない。

## スラスター・着陸補助

ClientSimで実施: 姿勢誤差の収束、角速度減衰、要求トルクとノズルの対応、排気方向の車体追従、接地前の霧、噴射停止後の残留・消滅、高さ7 m/降下11 m/sの補助オン・オフ比較、前進速度維持、接地後の反発と静止、粒子数上限。Play Mode限定の平面台で、飛行許可中の緩い降下から接地することも確認。

物理力は既存の owner ガード内だけにあることをソース確認しました。残る実機受入: 非 owner の姿勢/着陸力が無いことと噴射表示、途中参加・所有権変更・0.6秒以上の受信停止、VRから見た半透明煙の負荷と視認性。斜面、端、極端な降下速度、逆さまの低高度進入も追加検証が必要です。映像の接地減速度や実車の反発特性を測定した結果ではありません。
