# VR右トリガー加速の修正 — 2026-10-22

対象の変更前コミット: `cdf5ae7f996a0f286ed295760c7446f61e074af4`。

## 原因と変更

変更前は `yokeHeld && rightUseHeld` を満たすときだけ正のスロットルを出し、ヨーク未取得時は左スティック操舵も0にしていた。ヨーク取得は右手が中心から0.32m以内にあり、両トリガーを離して右グリップを押すことが条件。このため、トリガーだけを押しても走行できなかった。また、乗車前から右グリップを保持すると、取得範囲外でも中立待ちを解除できなかった。

右Useによる前進と左スティック横の操舵／yawをヨーク取得から独立させ、VRの通常走行の中立判定からグリップと未使用のデスクトップ入力を除いた。左右Use・Jump・左スティック横は引き続き中立に戻す必要がある。左右同時は左Useの制動が優先する。

取得済みヨークの解放／距離超過では、保持中の右Useをラッチで無効にする。右Useの解放イベントでラッチを解除し、押し直せばヨークを再取得せず走行できる。姿勢操作とJump上昇はヨーク保持を引き続き要求する。パネル操作、休止、所有権通知、乗降等での入力解除も維持した。右グリップを握っていても加速できない実機の全ケースを、この再現だけで説明できるとは限らない。

車内の入力状態・ヘルプ、入口の走行／VR看板、操作資料を更新。看板PNGは既存の `SourceAssets/build_airport_signs.py` で文字から再生成したUI素材であり、ゲームプレイの撮影画像ではない。

## 再現

1. Unity 2022.3.22f1とVRChat Worlds SDK 3.10.5の作業コピーで、通常のC#インポートを完了させる。
2. `Drive Roadster → Validate VR trigger acceleration in isolated scene`、または `RoadsterVRInputValidation.Begin()` を実行する。
3. 保存確認後、新規の `Assets/RoadsterVRInputFixture*.unity` を生成してPlay Modeに入り、約20秒間の入力試験を行う。既存空港シーンの再構築は行わない。テストシーンはプロジェクトに残る。
4. 結果は `docs/validation/vr-trigger-regression.json`。バッチ実行では `-roadsterInputReport <JSONの絶対パス>` で保存先を変更し、`-roadsterExit` で検査後にUnityを終了できる。Unityの `-quit` は付けない。失敗時は終了コード1。

この試験は動いている車両Runtimeの確認用。空港全体の走行、見た目、ネットワーク性能を再検証するものではない。合成した `SteamVR2` 識別は、実機で検出した入力方式ではない。

## 適用と残る確認

修正版のソースをUnityで再インポートし、UdonSharpのコンパイル完了を確認してからビルドする。既存の看板のテクスチャ参照は同じため、新しいPNGが反映される。シーン再生成は不要。この作業ではVRChatワールドを再アップロードしていないため、配信中のワールドは自動で更新されない。

実HMD／コントローラー、Quest Link・Air Link・Virtual Desktop等の接続経路、リマップ、実VRChatでのメニュー復帰、複数クライアントでの所有権移譲は未検証。実機では乗車後に両トリガー・Jump・左スティック横を離し、グリップなしで右トリガー加速・左トリガー制動・左スティック操舵を確認する。SDK上のUseは通常trigger、Grabは通常gripで、リマップに従う：[VRChat公式入力イベント](https://creators.vrchat.com/worlds/udon/input-events/)。
