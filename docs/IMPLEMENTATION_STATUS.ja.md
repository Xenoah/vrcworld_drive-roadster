## 同期方式

初期実装はManualスナップショットで位置・姿勢・速度を同期し、非ownerはkinematicで描画補間する。VRCObjectSyncは併用しない。車両と記録のManual UdonBehaviourは同じGameObject上で同じownerを共有する。車輪はローカル演出で、個別Transformを同期しない。

これは設計書で比較候補とした方式の一つであり、ネットワーク負荷と実機の見え方を確認して採否を決める。定期送信間隔0.12秒は暫定値。

## 残る重要リスク

- 同時乗車: 0.4秒待機はネットワーク合意の証明ではない。新ownerの占有確定までに要求が競合する窓がある。owner喪失時は退出するが、実際のイベント順序を複数人で確認して必要なら管理オブジェクト予約方式へ移行する。
- 初回状態: IsNetworkSettledと最初のsnapshotを乗車条件にしているが、ClientSimと実クライアントで待機解除を確認する。
- UdonSharp 対応 API: SDK 3.10.5 でコンパイルと限定実行を確認。未実行の分岐や将来の SDK との互換性は別途検証。
- ショートカット: 通常走行のゲート検証であり、改造クライアントや全ての境界外経路を防ぐ認証ではない。
- 高品質な静止モデルと、VR内で快適に運転できる品質は別。後者はUnity/VRChatでの反復調整が必要。

## 2026-10-17 クラウド段階の修正（以下は当時の履歴）

- Builderのローカル変数名重複（CS0136候補）をlodPath/scenePathへ分離。専用回帰チェック3件追加。
- ゲート判定の位置をRigidbody.positionへ統一し、物理modeと座標基準を一致。
- 遠隔HUD速度は受信netVelocityを使うアクセサへ変更。
- C#4ファイルの構文解析、Python静的/数理33件を実行し成功。Unity/Udonコンパイルと実機試験は引き続き未実施。
- 公式映像からの再現は原寸/性能の保証ではない。車体前面の細部とVRでの見え方は追加調整が必要。

## スラスターと着陸補助の追加

公式映像を時刻付きで再観察し、車体に追従するジェット、ワールド空間の残留煙、路面命中から広がる霧を追加。既存 owner ガードと Manual 同期を維持しています。[詳細](THRUSTERS.ja.md)。

## 車内と入力の更新

[車内技術資料](COCKPIT.ja.md)。移動入力によるStation退出を無効にし、X／EXITで安全に降車（Jumpは操縦専用）。遊び・感度・入力平滑化・走行中リセット確認を追加。原本と全LODを更新。車内の実データ表示と入力連動をClientSimで検証した。Auto/Manual・独立着陸補助・右手仮想ヨークを追加し、R復帰をBackspaceへ変更。[Meta公式API/OpenXRとの対応調査](INPUT_BINDINGS_META.ja.md)も掲載。
